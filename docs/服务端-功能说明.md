# 服务端功能说明

服务端没有给消费者点的页面。它是一直开着的程序：用户端和管理端把「登录、看商品、送礼下单、付款、领取、发货」这些请求发给它，它检查是否允许、把结果存进数据库，必要时再去问微信、支付宝、短信、对象存储这些外面的服务。

可以把它理解成总台。两个前台（用户端、管理端）说的话，都由总台记账，并在需要时给外面的公司打电话。

数据库配置在 `GiftMall-server/sqx-admin/src/main/resources/application-dev.yml`（本地）和 `application-prod.yml`（线上）。库名默认 `gift-mall`，初始化脚本是 `GiftMall-server/db/gift-mall.sql`。商品、卡面、订单、支付、优惠券、钱包、分销都记在这里。

启动类是 `com.sqx.SqxAdminApplication`。端口是 **9191**，所有接口都在 `/sqx_fast` 下面。接口列表在：

http://127.0.0.1:9191/sqx_fast/swagger-ui.html

Redis 写在配置里，地址是本机 `6379`。当前 `spring.redis.open` 和 `sqx.redis.open` 都是关的，所以它不是必须先启动的服务。如果以后把开关打开，就要先启动 Redis。

下面先说它为两个前台做哪些事，再说它会主动连接哪些外面的服务。

## 它为消费者（用户端）做的事

这些都是用户在手机里点一下之后，由服务端完成的：

- **注册和登录**：检查手机号和短信验证码，或检查密码；也支持微信小程序登录、绑定手机号。通过后发给用户一张登录凭证（JWT，请求头名是 `token`）。之后需要登录的接口都要带这张凭证。
- **首页与商品**：返回轮播图、分类、卡面推荐、特价好礼、商品列表与详情、规格 SKU、搜索。
- **购物车**：加购、改数量、删除、结算。
- **送礼下单**：生成礼物订单，关联商品、卡面、祝福语等；下单时锁库存。
- **支付结果入账**：微信、支付宝通知到来，或用户用余额支付成功后，把订单改成已支付；送礼单进入「待赠送」，普通购买单进入已付款流程。
- **分享与领取**：支付成功后可分享；对方领取时填写收货地址，订单进入「待发货」。
- **优惠券**：领券、用券。
- **邀请分销**：记录邀请关系，展示团队与收益；确认收货后发放佣金。
- **钱包**：余额、充值档位、提现申请、资金明细。提现只生成一条待审核记录，不会在这一步把钱转到对方支付宝或微信。
- **发票**：申请开票、查看开票记录。
- **消息、帮助、协议、反馈、注销**：把后台维护的内容发给用户端，或记下注销申请。

## 它为管理端做的事

- 工作人员登录（验证码 + 密码），并按角色限制能看的菜单。验证码也由它生成。
- 提供运营数据概览要用的统计数字。
- 保存用户、商品、分类、规格、订单、财务、优惠券、卡面祝福、首页装修、发票、帮助相关数据。
- 订单发货、提现审核、发票审核一类按钮会改订单或资金状态。原路退回微信或支付宝时，仍然要支付密钥有效。
- 保存系统配置（主要在 `common_info`）。用户端下次请求时读到新的短信、支付、图片存储等配置。
- 管理员、角色、菜单、App 升级配置。

## 对接了哪些外面的服务

下面每一项都是服务端真的会向外发送请求的。密钥没填时，它不会假装成功，用户端会看到失败提示。

密钥主要写在数据库的 `common_info` 表里，管理端「系统配置」负责改。改完保存后，下次请求才会用新值。

### 短信

注册、验证码登录、找回密码，都由服务端发短信。

可以切换服务商（腾讯云短信、阿里云短信、短信宝）。只把程序跑起来，不会自动拥有短信额度。短信签名和模板要在对方网站申请。

### 微信支付

用户选择微信支付时，服务端用商户号和密钥向微信支付下单，并把拉起支付需要的信息交回手机。支付完成后，微信访问服务端的通知地址，服务端核对之后，再把订单改成已支付。

还需要微信公众平台上的小程序或公众号 AppId：https://mp.weixin.qq.com/ 。商户平台在 https://pay.weixin.qq.com/ 。

### 支付宝

和微信同一类流程：下单、拉起支付宝、等待支付宝通知。需要支付宝开放平台的应用编号和密钥：https://open.alipay.com/ 。

### 图片存储

用户和管理端上传的图片（头像、商品图、轮播、卡面）由服务端接收。当前上传入口默认走本地存储；也可按「系统配置」对接阿里云 OSS 等。没配好时，上传接口会失败。

### 地图

收礼填写收货地址、经纬度反查等能力会用到地图相关密钥。密钥要自己申请。

### 物流查询

订单物流轨迹查询依赖第三方物流接口配置。没配时，物流查询会失败，不影响本地下单发货记账。

## 这些不是外面的公司

- **余额支付**：只改数据库里的钱包数字。
- **提现**：只保存收款账号和金额，等管理端审核。没有默认自动打进微信零钱或支付宝。
- **邀请分成、优惠券规则**：都在自己的数据库里计算。
- **订单状态、库存扣减、卡面祝福绑定**：支付与领取后的站内记账。
- **站内消息、帮助文章、协议正文、轮播**：读自己的库。
- **操作日志、权限、角色**：只约束管理端工作人员。

## 送礼主流程（服务端视角）

1. 用户端选择卡面、礼物、祝福语，请求生成订单（状态：待付款）。
2. 用户选择微信、支付宝或余额支付。
3. 支付成功后，送礼订单进入「待赠送」；服务端记录支付信息，并可预写分销佣金。
4. 用户发起分享，生成可领取的分享记录。
5. 对方登录后领取，填写收货地址，订单进入「待发货」。
6. 管理端发货后，订单变为「已发货」；用户确认收货后变为「已收货」，并发放分销佣金。
7. 超时未领取时，定时任务会按系统配置处理失效与退款相关逻辑（微信/支付宝原路退款需密钥有效）。

普通商城自购订单支付成功后，走「已付款 → 发货 → 收货」链路，不会进入「待赠送」。

## 两个前台怎样和它配合

用户端和管理端都不直接保存订单。它们把请求发给服务端，服务端再决定要不要去问微信、短信或图床。

所以：

- 服务端没启动时，两个网站都能打开界面，但登录、列表、付款都会失败。
- 外面的密钥只配在服务端能读到的「系统配置」里。只在用户端页面上改文字，不会变成已经开通了微信支付。
- 管理端改完轮播、优惠券、商品、帮助并保存后，用户端下次打开才会看到新内容。
- 要测完整送礼，还需要在管理端上好商品与卡面，并在用户端注册账号、配好支付与短信。
